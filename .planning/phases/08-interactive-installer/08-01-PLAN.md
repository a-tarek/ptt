Create the `internal/installer` package with three files:

**paths.go** — RC file path resolution:
- `RCFilePath(shellType string) (string, error)` — returns the default rc file path for a shell:
  - "zsh" → `~/.zshrc`
  - "bash" → `~/.bashrc` (also check: if `~/.bash_profile` exists but `~/.bashrc` does not, return `~/.bash_profile` — common on macOS)
  - "fish" → `~/.config/fish/config.fish`
  - Other → error
- Use `os.UserHomeDir()` for `~` resolution

**rcfile.go** — Core RC file operations:

Constants/vars:
- `MarkerBegin = "# >>> wt >>>"` and `MarkerEnd = "# <<< wt <<<"` (conda/certbot style markers)
- V1 detection patterns: look for lines containing `source` and `wt.zsh` (e.g., `source ~/.oh-my-zsh/custom/plugins/wt/wt.zsh`, `source /path/to/wt.zsh`, `. ~/wt.zsh`)

Functions:
- `EvalLine(shellType string) string` — returns the eval line for a given shell. For bash/zsh: `eval "$(wt shell-init)"`. For fish: `wt shell-init | source`. Note: shell-init auto-detects shell from $SHELL, so the eval line doesn't need shell name argument.
- `MarkerBlock(shellType string) string` — returns the full marker block string:
  ```
  # >>> wt >>>
  # Managed by wt installer — do not edit this block manually
  eval "$(wt shell-init)"
  # <<< wt <<<
  ```
  (For fish, use `wt shell-init | source` instead of eval)
- `HasMarkerBlock(content string) bool` — returns true if content contains MarkerBegin
- `FindV1Lines(content string) []int` — returns 0-indexed line numbers that look like wt v1 entries. Scan each line: if it matches pattern `source.*wt\.zsh` or `\.\s+.*wt\.zsh` (dot-source), return that line index. Be careful with comment lines — only match non-commented lines (lines NOT starting with #).
- `CommentOutLines(lines []string, indices []int) []string` — returns a copy of lines with the given indices commented out (prepend `# [wt v2 migration] ` to each). Return new slice, don't mutate input.
- `InsertMarkerBlock(content string, shellType string) string` — adds the marker block to end of content. If content doesn't end with newline, add one first. Then append the marker block followed by a newline.
- `RemoveMarkerBlock(content string) string` — removes everything from MarkerBegin line through MarkerEnd line (inclusive). Preserve surrounding content. If marker block not found, return content unchanged.
- `BackupFile(filePath string) (string, error)` — copies filePath to filePath + ".wt-backup", returns backup path. Use `os.ReadFile` + `os.WriteFile` to copy with same permissions.
- `RestoreBackup(backupPath, originalPath string) error` — copies backup back to original path, removes backup file.

**rcfile_test.go** — Unit tests covering:
- `HasMarkerBlock`: true when present, false when absent
- `FindV1Lines`: finds `source ~/wt.zsh`, finds `. /path/to/wt.zsh`, ignores commented lines, returns empty for no matches
- `CommentOutLines`: correctly comments specified indices, doesn't mutate input
- `InsertMarkerBlock`: appends block, handles content with/without trailing newline, idempotent check (caller uses HasMarkerBlock first)
- `RemoveMarkerBlock`: removes block cleanly, handles block at end of file, returns unchanged content when no block
- `MarkerBlock`: correct format for bash/zsh and fish
- `EvalLine`: correct for bash/zsh vs fish

Create `cmd/install.go` — the `wt install` cobra command with a guided, interactive walkthrough.

**Command setup:**
- `Use: "install"`, `Short: "Set up wt shell integration"`
- NOT hidden (this is user-facing, unlike shell-init)
- `Args: cobra.NoArgs`

**Walkthrough flow (in RunE):**

The command reads from stdin for user confirmation. Use `bufio.NewReader(os.Stdin)` for input.

Step 1 — Detect shell:
```
wt install — Shell Integration Setup
=====================================

Step 1: Detecting shell...
  Detected: zsh

Continue with zsh? [Y/n]
```
- Call `shell.DetectShell()` to get shell type
- If detection fails, print error with supported shells list and manual instructions (the full copy-paste block), then exit 1
- Read user input. If empty or "y" or "Y", continue. If "n" or "N", print manual instructions and exit 0. Any other input, ask again (or treat as decline).

Step 2 — Check RC file:
```
Step 2: Checking configuration...
  RC file: ~/.zshrc
```
- Call `installer.RCFilePath(shellType)` to get rc file path
- Read rc file content (if file doesn't exist, that's ok — we'll create it)
- Display path relative to home (use `~` prefix for readability)

Step 3 — Check for existing installation:
- Call `installer.HasMarkerBlock(content)` — if true:
  ```
  wt is already configured in ~/.zshrc
  No changes needed.
  ```
  Exit 0. (Idempotent behavior.)

Step 4 — Detect v1 entries:
- Call `installer.FindV1Lines(content)` — if any found:
  ```
  Step 3: Migrating from wt v1...
    Found v1 entry on line 42: source ~/.oh-my-zsh/custom/plugins/wt/wt.zsh
    This will be commented out and replaced with the v2 configuration.
  ```

Step 5 — Show changes:
```
Step 4: The following will be added to ~/.zshrc:

  # >>> wt >>>
  # Managed by wt installer — do not edit this block manually
  eval "$(wt shell-init)"
  # <<< wt <<<

{If v1 migration:}
  The following line will be commented out:
    Line 42: source ~/.oh-my-zsh/custom/plugins/wt/wt.zsh

Proceed? [Y/n]
```
- Read user input. If decline:
  ```
  No changes made. To set up manually, add this to your ~/.zshrc:

    eval "$(wt shell-init)"
  ```
  Exit 0.

Step 6 — Apply changes:
- Call `installer.BackupFile(rcFilePath)` (if file exists) — print: `  Backing up ~/.zshrc → ~/.zshrc.wt-backup`
- If v1 lines found, apply `installer.CommentOutLines()` to the lines, then rejoin
- Call `installer.InsertMarkerBlock()` on the (possibly modified) content
- Write the new content to the rc file using `os.WriteFile` with 0644 permissions
- If ANY step fails: call `installer.RestoreBackup()` if backup was made, print error, exit 1

Step 7 — Success:
```
Done! wt has been configured for zsh.

To activate, either:
  • Restart your terminal
  • Run: source ~/.zshrc
```
(For fish: `source ~/.config/fish/config.fish`)

**Error handling / rollback:**
- Wrap the write operations in a pattern where if writing the new content fails, the backup is restored
- Print clear error message on failure: what went wrong and how to fix

**Notes:**
- Use `fmt.Fprintf(os.Stderr, ...)` for all walkthrough output (prompts, status messages). This follows the project pattern where stderr is for user interaction.
- Actually, for the install command specifically, stdout is fine since this is an interactive command (not piped). Use `fmt.Printf` / `fmt.Println` for walkthrough output. The shell-init command uses stdout for eval content, but install is different — it's a user-facing interactive flow.
- For the "display path" helper: replace home dir prefix with `~` for display purposes.
