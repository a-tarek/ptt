  <name>Task 1: Implement wt new command</name>

  <action>
Create `cmd/new.go` implementing the `wt new` command.

**Flags** (package-level vars, registered in `init()`):
- `--config <name>` (string): use `.wtconfig-<name>` instead of default `.wtconfig`
- `--skip-config` (bool): skip all config actions
- `--copy` ([]string): inline copy overrides (repeatable)
- `--symlink` ([]string): inline symlink overrides (repeatable)

**Command definition:**
- Use: `"new <name>"`, Short: `"Create a new worktree"`, Args: `cobra.ExactArgs(1)`

**RunE logic (in order):**

1. **Check git repo**: `git.IsInsideGitRepo()` -> error "not inside a git repository"

2. **Get repo root**: Call `git.GetHomePath()` to get the home worktree path. This is the base for placement calculations. Also get the current worktree root via `git.CurrentWorktreeRoot()` for use as config source.

3. **Compute target path**: Call `git.WorktreePath(homePath, name)` where `name = args[0]`. This handles bare vs sibling mode automatically. If it returns error (path exists), return that error.

4. **Determine branch**: `branchName := name`. The branch name equals the worktree name (per CONTEXT.md: "Accepts branch name as required argument"). Replace "/" with "-" in the directory name portion only for the path computation. Actually, the name IS the branch name -- so `wt new feature-login` creates branch `feature-login`. The worktree directory name uses the same name passed to WorktreePath.

5. **Create worktree**: Try `git worktree add <targetPath> -b <branchName>` first (creates new branch from HEAD). If that fails (branch already exists), try `git worktree add <targetPath> <branchName>` (uses existing branch). If both fail, return error. Use `exec.Command` with `CombinedOutput()` for error messages.

6. **Handle config** (only if `--skip-config` is false):
   a. Determine config source root: use `currentWorktreeRoot` from step 2 (this is where we copy files FROM).
   b. Resolve config path: If `--config` flag is set, call `config.ResolveConfigPath(homePath, configFlagValue)`. If not set, call `config.ResolveConfigPath(homePath, "")` for default .wtconfig.
   c. If config file not found: silently skip (this is normal -- .wtconfig is optional). Check by inspecting the error from ResolveConfigPath.
   d. If config file found: call `config.ParseFile(configPath)` then `config.ValidateActions(srcRoot, actions)`.
   e. Handle inline flags: If `--copy` or `--symlink` flags are present, call `config.BuildActionsFromFlags(copyFlags, symlinkFlags, nil)` and merge: `config.MergeFlags(configActions, flagActions)`. Note: MergeFlags is not in the codebase. Instead, just append flag actions after config actions. Check for `config.CheckDuplicatePaths(copyFlags, symlinkFlags)` first.

   WAIT -- re-check the config package. The function is `BuildActionsFromFlags` (not `ParseFlags`) and there's no `MergeFlags`. The merge behavior per CONTEXT.md is: "--copy/--symlink inline overrides merge with whatever config is loaded". The simplest merge: append flag actions to config actions. Since CheckDuplicatePaths only checks within flags (not across config+flags), this is safe.

   f. Execute actions: `setup.ExecuteActions(srcRoot, targetPath, mergedActions)`. If this fails, the executor already handles rollback (removes the worktree directory). Return the error.

7. **Config action count**: Track how many config actions were applied for the confirmation message.

8. **Confirmation messages** (to stderr):
   - "Created worktree {basename} (branch: {branchName})"
   - If config was applied: "Applied {configFileName} ({N} actions)"
   - "Switched to {basename} (branch: {branchName}, {clean|dirty})"

   Check dirty status of the new worktree after config actions run (config may create files that are untracked).

9. **Output path** (to stdout): If `outputPath` flag is true (from goto.go's package-level var), print just the target path to stdout via `fmt.Println(targetPath)`. If false, print the confirmation messages to stdout as well.

**Flag hierarchy** (per CONTEXT.md):
- Default: load `.wtconfig` if it exists
- `--config ci`: load `.wtconfig-ci` instead (errors if not found)
- `--skip-config`: skip everything (no config loaded, no flag actions either? Actually no -- per CONTEXT.md: "--copy/--symlink merge on top". So --skip-config skips file-based config but --copy/--symlink STILL apply even with --skip-config. Re-read: "Flag hierarchy: default .wtconfig < --config override < --skip-config bypass; --copy/--symlink merge on top". This means --copy/--symlink are independent of --skip-config.)

Correction on flag hierarchy:
- `--skip-config` only skips file-based config (.wtconfig or .wtconfig-<name>)
- `--copy`/`--symlink` ALWAYS apply (they "merge on top" independent of skip)
- So if `--skip-config --copy .env` is passed: skip .wtconfig but still copy .env
