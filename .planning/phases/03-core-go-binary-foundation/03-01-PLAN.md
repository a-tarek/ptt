<task type="auto">
  <name>Task 1: Initialize Go project with cobra root command and version</name>
  <files>main.go, go.mod, cmd/root.go, cmd/version.go, internal/git/worktree.go</files>
  <action>
    **Prerequisites:** Ensure Go is installed. If `go version` fails, install via `brew install go`.

    **1. Initialize Go module:**
    - Run `go mod init github.com/ahmedelarabyy/wt` (or appropriate module path — use a reasonable Go module path)
    - The module name should be short; `github.com/user/wt` is conventional

    **2. Create `main.go`:**
    - Minimal entry point: imports `cmd` package, calls `cmd.Execute()`
    - If Execute returns error, os.Exit(1)

    **3. Create `cmd/root.go`:**
    - Define `rootCmd` as cobra.Command with Use: "wt", Short: "Git Worktree Manager"
    - Long description matching wt.zsh usage text (commands: new, goto, home, init, eject, list, merge, rebase, delete)
    - `Execute()` function that calls `rootCmd.Execute()` and returns error
    - Set `rootCmd.SilenceUsage = true` and `rootCmd.SilenceErrors = true` — we handle errors ourselves
    - In Execute(), if error occurs, print `error: <msg>` to stderr and return the error
    - Error format: `fmt.Fprintf(os.Stderr, "error: %s\n", err)` — git-style terse messages

    **4. Create `cmd/version.go`:**
    - Add `--version` flag to rootCmd (not a subcommand)
    - Version variable: `var Version = "dev"` (will be set via ldflags at build time)
    - When `--version` is passed, print version string and exit 0
    - Use cobra's built-in version mechanism: `rootCmd.Version = Version` and set `rootCmd.SetVersionTemplate("wt version {{.Version}}\n")`

    **5. Create `internal/git/worktree.go`:**
    - Package `git`
    - Define `Worktree` struct: `Path string`, `Branch string`, `IsBare bool`, `IsDetached bool`
    - Function `ListWorktrees() ([]Worktree, error)`:
      - Execute `git worktree list --porcelain`
      - Parse output line by line: `worktree <path>`, `branch refs/heads/<name>`, blank line separates entries
      - Handle `bare` and `detached` lines
      - Return slice of Worktree structs
    - Function `IsDirty(path string) (bool, error)`:
      - Execute `git -C <path> status --porcelain`
      - If output is non-empty, worktree is dirty
      - Return bool
    - Function `CurrentWorktreeRoot() (string, error)`:
      - Execute `git rev-parse --show-toplevel`
      - Return trimmed path
    - Function `IsInsideGitRepo() bool`:
      - Execute `git rev-parse --git-dir`
      - Return true if exit code 0
    - All git commands use `os/exec` with `exec.Command("git", args...)`
    - Capture both stdout and stderr for error messages

    **6. Wire up and test:**
    - Run `go mod tidy` to fetch cobra dependency
    - Run `go build -o wt .` to verify compilation
    - Run `./wt --version` — should print "wt version dev"
    - Run `./wt --help` — should show usage with command list
  </action>
  <verify>
    - `go build -o wt .` succeeds with no errors
    - `./wt --version` outputs "wt version dev"
    - `./wt --help` outputs usage text listing commands
    - `echo $?` is 0 for both
  </verify>
  <done>Binary builds, --version prints "wt version dev", --help shows usage, proper exit codes</done>

  <name>Task 2: Implement wt list and wt init commands</name>
  <files>cmd/list.go, cmd/init_cmd.go</files>
  <action>
    **1. Create `cmd/list.go` — implement `wt list`:**

    Per user decisions:
    - Default columns: name (directory basename), branch, dirty/clean status indicator
    - Current worktree marked with asterisk prefix (`*`) — like `git branch`
    - Color auto-detected: color when stdout is a terminal, plain when piped
    - Path shown only with `--all` / `-a` flag
    - Empty state: silent (no output, exit 0) — script-friendly

    Implementation:
    - Create `listCmd` as cobra.Command with Use: "list", Short: "List all worktrees", Aliases: []string{"ls"}
    - Add `--all` / `-a` bool flag to show paths
    - In RunE:
      1. Check `git.IsInsideGitRepo()` — if not, return error "not inside a git repository"
      2. Call `git.ListWorktrees()` to get all worktrees
      3. If empty slice, return nil (silent exit 0)
      4. Call `git.CurrentWorktreeRoot()` to get current path
      5. For each worktree, call `git.IsDirty(wt.Path)` to check status
      6. Dirty indicator: use `~` for dirty, nothing (space) for clean (Claude's discretion — tilde is widely understood and works without Unicode)
      7. Format output with aligned columns using fmt.Fprintf:
         - `* %-30s %-20s %s` for current worktree
         - `  %-30s %-20s %s` for other worktrees
         - When `--all`, append path column
      8. Use `fatih/color` for colored output:
         - Current worktree name in green
         - Branch in default color
         - Dirty indicator `~` in yellow
         - Color auto-detects TTY via fatih/color's built-in mechanism
    - Register: `rootCmd.AddCommand(listCmd)` in init()

    **2. Create `cmd/init_cmd.go` — implement `wt init`:**

    Per user decisions:
    - Template contains commented-out examples showing copy/symlink/run syntax
    - Error if .wtconfig already exists — no overwrite (no --force)
    - Created in current directory (not necessarily repo root)
    - Requires being inside a git repo — error if not
    - Silent on success — actually, looking at wt.zsh, it prints "Created <path>". Per decisions, "simple commands silent on success". So: silent on success.

    Wait — re-reading the decisions: "Simple commands silent on success (init, delete)". So init is silent on success.

    Implementation:
    - Create `initCmd` as cobra.Command with Use: "init", Short: "Create .wtconfig template"
    - In RunE:
      1. Check `git.IsInsideGitRepo()` — if not, return error "not inside a git repository"
      2. Get current directory with `os.Getwd()`
      3. Check if `.wtconfig` exists at current directory — if yes, return error ".wtconfig already exists"
      4. Write template to `.wtconfig` in current directory
      5. Template content (note the `run` action is included per user's specific idea about abstract actions):

    ```
    # .wtconfig — actions to run when creating new worktrees
    #
    # Actions:
    #   copy <path>       Copy file or directory from source worktree
    #   symlink <path>    Symlink to source worktree's file or directory
    #   run <command>     Run a shell command in the new worktree
    #
    # Examples:
    #
    # copy .env.local
    # copy .env
    # symlink node_modules
    # symlink .venv
    # symlink target
    # run npm install
    ```

      6. Return nil (silent success, exit 0)
    - Register: `rootCmd.AddCommand(initCmd)` in init()

    **3. Wire up and test:**
    - Run `go mod tidy`
    - Run `go build -o wt .`
    - Inside a git repo: `./wt list` — should show worktrees
    - Inside a git repo: `./wt init` — should create .wtconfig, then verify file exists
    - Run `./wt init` again — should error "error: .wtconfig already exists"
    - Outside a git repo: `./wt list` — should error "error: not inside a git repository"
    - Clean up: `rm .wtconfig` after testing
  </action>
