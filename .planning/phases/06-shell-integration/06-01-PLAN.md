Create the `internal/shell/` package with three components:

**1. detect.go** - Shell detection from $SHELL env var:
- `DetectShell() (string, error)` reads `os.Getenv("SHELL")`, extracts `filepath.Base()`, and returns "bash", "zsh", or "fish"
- Returns error if SHELL is unset or if shell is not one of the three supported
- Error message: `"SHELL environment variable not set"` or `"unsupported shell: %s (supported: bash, zsh, fish)"`

**2. detect_test.go** - Unit tests for DetectShell:
- Test with SHELL=/bin/bash -> returns "bash"
- Test with SHELL=/usr/local/bin/zsh -> returns "zsh"
- Test with SHELL=/usr/bin/fish -> returns "fish"
- Test with SHELL=/bin/csh -> returns error
- Test with SHELL="" (unset) -> returns error
- Use `t.Setenv()` to temporarily override SHELL in tests

**3. embed.go** - go:embed directives and wrapper retrieval:
- Package `shell`
- `import _ "embed"`
- Three `//go:embed templates/wrapper.bash` (and .zsh, .fish) variables as `string`
- `GetWrapper(shellName string) (string, error)` - returns the embedded wrapper for the given shell name, or error for unsupported shell

**4. wrapper.bash** - Bash wrapper function (bash 3.2+ compatible):
```bash
wt() {
  local result
  result=$(command wt --output-path "$@")
  local exit_code=$?

  if [ $exit_code -eq 0 ] && [ -n "$result" ]; then
    cd "$result" || return 1
  fi

  return $exit_code
}
```
Key constraints for bash 3.2+:
- Use `[ ]` not `[[ ]]` for conditionals
- Use `=` not `==` for string comparison
- Use `local` for variable declarations
- Use `"$@"` for argument passthrough
- Use `command wt` to bypass function and call binary

**5. wrapper.zsh** - Zsh wrapper function:
```zsh
wt() {
  local result
  result=$(command wt --output-path "$@")
  local exit_code=$?

  if [ $exit_code -eq 0 ] && [ -n "$result" ]; then
    cd "$result" || return 1
  fi

  return $exit_code
}
```
Zsh and bash share the same wrapper syntax -- POSIX-compatible constructs work in both. Keep them identical for maintainability. Do NOT use any zsh-only features (no `path` variable -- it clobbers PATH in zsh per project memory).

**6. wrapper.fish** - Fish wrapper function:
```fish
function wt
  set -l result (command wt --output-path $argv)
  set -l exit_code $status

  if test $exit_code -eq 0 -a -n "$result"
    cd "$result"; or return 1
  end

  return $exit_code
end
```
Fish-specific syntax: `set -l` for locals, `$argv` for args, `$status` for exit code, `test` for conditionals, `function ... end` blocks.

All three wrappers follow the same pattern: route ALL commands through the wrapper (not just cd commands). Non-cd commands (list, delete, merge, rebase) produce no stdout when --output-path is set, so the wrapper simply passes through their exit code without running cd. This gives a simpler mental model (one function for all wt commands, like zoxide).

Create `cmd/shell_init.go` with a new cobra command:

```go
var shellInitCmd = &cobra.Command{
    Use:    "shell-init",
    Hidden: true,
    Short:  "Output shell wrapper function for eval",
    Long:   "Outputs shell-specific wrapper code. Add to your rc file:\n  eval $(wt shell-init)",
    Args:   cobra.NoArgs,
    RunE: func(cmd *cobra.Command, args []string) error {
        shellType, err := shell.DetectShell()
        if err != nil {
            return err
        }
        wrapper, err := shell.GetWrapper(shellType)
        if err != nil {
            return err
        }
        fmt.Print(wrapper)
        return nil
    },
}
```

Key details:
- Import `"github.com/ahmedelarabyy/wt/internal/shell"`
- `Hidden: true` per user decision -- this is a plumbing command for rc files, not user-facing
- `Args: cobra.NoArgs` -- no arguments, shell is auto-detected from $SHELL
- Output goes to stdout (for `eval $()` capture) with `fmt.Print` (no trailing newline beyond what the script contains)
- Errors go to stderr via Cobra's error handling (already configured in root.go)
- Register with `rootCmd.AddCommand(shellInitCmd)` in `init()`
