<task type="auto">
  <name>Task 2: Release workflow triggered by version tags</name>
  <files>.github/workflows/release.yml</files>
  <action>
Create `.github/workflows/release.yml` with:

**Trigger:** push tags matching `v*` (e.g., v2.0.0, v2.1.0-beta)

**Jobs:**

**Job 1: test** (reuse CI steps)
- Same OS matrix as CI
- Run `go test ./...` to ensure tests pass before release

**Job 2: release** (needs: test)
- Runs on ubuntu-latest only
- Steps:
  1. Checkout code (with `fetch-depth: 0` for goreleaser tag access)
  2. Set up Go
  3. Set up Node.js (for npm publish) -- use `actions/setup-node@v4` with `registry-url: 'https://registry.npmjs.org'`
  4. Install goreleaser: `goreleaser/goreleaser-action@v6` with `install-only: true`
  5. Run goreleaser: `goreleaser release --clean` (NOT snapshot mode -- this is a real release)
  6. Stage npm binaries: `bash scripts/build-npm.sh` -- wait, goreleaser release already builds. The build-npm.sh uses `goreleaser build --snapshot`. For release, goreleaser release handles the build. We need to copy binaries from dist/ to npm/ after goreleaser release.

     Actually, re-examine: `goreleaser release --clean` produces binaries in dist/ with the same structure as `goreleaser build --snapshot --clean`. So after goreleaser release, we can manually stage binaries into npm platform dirs using the same cp logic from build-npm.sh. Create a small inline step that copies binaries:
     ```
     cp dist/wt_darwin_arm64_v8.0/wt npm/platforms/darwin-arm64/bin/wt
     cp dist/wt_darwin_amd64_v1/wt npm/platforms/darwin-amd64/bin/wt
     cp dist/wt_linux_arm64_v8.0/wt npm/platforms/linux-arm64/bin/wt
     cp dist/wt_linux_amd64_v1/wt npm/platforms/linux-amd64/bin/wt
     chmod +x npm/platforms/*/bin/wt
     ```
  7. Extract version from tag: `VERSION=${GITHUB_REF_NAME#v}` (strip leading 'v')
  8. Run publish: `bash scripts/publish-npm.sh $VERSION`

  **Environment:** Set `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}` for npm publish
  **Permissions:** `contents: write` for goreleaser to create GitHub release

**Secrets required (documented in workflow comments):**
- `NPM_TOKEN`: npm automation token for publishing @potato/* packages

Name the workflow "Release".

Per user decision: release pipeline should be one-command -- push a tag and everything builds + publishes.
