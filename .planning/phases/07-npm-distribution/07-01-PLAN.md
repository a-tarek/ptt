<task type="auto">
  <name>Task 2: Create goreleaser config and npm package structure</name>
  <files>

  <action>
    Use the npm scope name chosen in Task 1 for all @SCOPE references below.

    **1. Create `.goreleaser.yaml` in project root:**
    ```yaml
    project_name: wt
    builds:
      - id: wt
        binary: wt
        main: ./main.go
        goos: [darwin, linux]
        goarch: [amd64, arm64]
        env: [CGO_ENABLED=0]
        ldflags:
          - -s -w
          - -X github.com/ahmedelarabyy/wt/cmd.Version={{.Version}}
    archives:
      - id: default
        format: binary
        name_template: "{{ .ProjectName }}_{{ .Os }}_{{ .Arch }}"
    ```
    Note: ldflags target `cmd.Version` (the Go variable in cmd/version.go), NOT `main.version`.

    **2. Create `npm/package.json` (main wrapper package):**
    ```json
    {
      "name": "@SCOPE/wt",
      "version": "0.0.0",
      "description": "Git worktree manager - fast, intuitive git worktree management",
      "repository": "github:ahmedelarabyy/wt",
      "license": "MIT",
      "bin": { "wt": "bin/wt" },
      "files": ["bin/wt"],
      "optionalDependencies": {
        "@SCOPE/wt-darwin-arm64": "0.0.0",
        "@SCOPE/wt-darwin-amd64": "0.0.0",
        "@SCOPE/wt-linux-amd64": "0.0.0",
        "@SCOPE/wt-linux-arm64": "0.0.0"
      },
      "engines": { "node": ">=18" }
    }
    ```
    Version starts at 0.0.0 -- the publish script will set real versions.

    **3. Create `npm/bin/wt` (Node.js wrapper script):**
    Follow the production-ready pattern from RESEARCH.md Pattern 3. Must include:
    - `#!/usr/bin/env node` shebang (Pitfall 6)
    - Platform map: darwin-arm64, darwin-x64 (maps to amd64), linux-x64 (maps to amd64), linux-arm64
    - `require.resolve()` for binary path resolution
    - `spawn()` with stdio: 'inherit' to forward all I/O
    - Error handling for unsupported platforms and missing packages
    - Signal forwarding on child exit

    IMPORTANT: Node.js uses "x64" for what Go calls "amd64". The platform map keys must use Node.js names (process.arch values), but package names use Go names (amd64). See RESEARCH.md Pattern 4 mapping table.

    **4. Create 4 platform package.json files:**
    Each in `npm/platforms/{platform}/package.json` where platform is darwin-arm64, darwin-amd64, linux-amd64, linux-arm64.

    Each must have:
    - `name`: `@SCOPE/wt-{platform}`
    - `version`: `"0.0.0"`
    - `os`: `["darwin"]` or `["linux"]`
    - `cpu`: `["arm64"]` or `["x64"]` -- NOTE: npm uses "x64" not "amd64" for cpu field
    - `bin`: `{ "wt": "bin/wt" }`
    - `files`: `["bin/wt"]`
    - `description`: Platform-specific description
    - `repository` and `license` matching main package

    Also create empty `npm/platforms/{platform}/bin/` directories (with .gitkeep files) so the structure is ready for goreleaser output.

    Do NOT create a `release` section in goreleaser -- we use goreleaser for local builds only, not GitHub Releases publishing.
